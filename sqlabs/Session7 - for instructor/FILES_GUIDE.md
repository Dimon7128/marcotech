# Session 7 — Which files are for whom?

Give students the entire [Session7 - for students/](<../Session7 - for students/>) folder. Its [README](<../Session7 - for students/README.md>) explains all 37 student files, the part objectives and the lab order. It contains no instructor keys or note-bearing deck.

| Instructor path | Purpose |
| --- | --- |
| README.md | Teaching index, preparation, build and QA instructions. |
| SESSION7_OVERVIEW.md | Each part’s name, objective, three main goals, slide range and timing. |
| output/Session7_Monitoring_Maintenance.pptx | Final 45-slide editable presentation with Hebrew notes and five objectives slides. |
| output/Session7_Monitoring_Maintenance.pdf | Slides-only preview. |
| slides/manifest.json | Part metadata, ordering, objectives and timing. |
| slides/part1/ through part5/ | Editable JSON sources and generated CONTENT.md teaching text/notes. |
| labs/lab1/ and lab2/ | Master exercises, data, expected results and Hebrew instructor guides. |
| labs/lab3/ and lab4/ | Master notebooks, complete report code, synthetic data, reports and separate Hebrew answer keys. |
| planning/ | Current plan, measured design rules and confirmed decisions. |
| reference/session6.pptx | Local style reference, copied from the reorganized Session 6 instructor package. |
| reference/EVIDENTLY_API.md | Tested reporting API and official documentation links. |
| assets/diagrams/ | Fifteen reusable SVG diagrams and native-diagram JSON definitions. |
| scripts/ | Build, render, content checks, lab verification, report capture, data generation and student synchronization. |
| requirements-presentation.txt, requirements-qa.txt | Presentation build and verification packages. |
| requirements-lab-qa.txt | Tested notebook/lab verification packages for a temporary instructor environment. |
| FINAL_QA_REPORT.md | Completed verification and practical limits. |
| output/qa/ | Small check records and generated slide manifest; inspection images/PDFs are reproducible and excluded after cleanup. |

The student handout has one start guide, LAB1.md–LAB4.md and the four lab folders. Lab 1 provides records and a worksheet. Lab 2 provides one TODO starter, two CSVs, requirements, a worksheet and calculated fallback. Labs 3–4 provide notebooks, complete scripts, required data, troubleshooting and prepared HTML/chart/summary fallbacks. Lab 4 also has its incident card, three optional hints and decision template.

Local environments, caches, duplicate ZIPs, obsolete part decks and inspection previews are not teaching materials. The final PPTX, student exercises, instructor answers, editable sources, synthetic data and report fallbacks are retained. Cleanup and source-preservation details are recorded in output/qa/organization-checks.json.
